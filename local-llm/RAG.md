# Локальная модель с RAG — ветка 28

В настройках выберите «Локальная — Qwen3.5 2B (Q4_K_M)»,
во вкладке «Индексы» — «С RAG», существующий индекс и режим обработки.
Подпись режима показывает, какая модель генерирует ответ, и обновляется
при выборе модели или восстановлении чата. «Без RAG» отключает поиск.

Используется уже существующий общий маршрут `/api/chat` → `searchBook`
→ `Agent` → локальный провайдер. Поиск читает `data/document-index/*.sqlite`,
эмбеддинг запроса строится локально через `nomic-embed-text` в Ollama.
При выборе локальной модели rewrite, память и генерация также идут в Ollama
на `127.0.0.1:11434`. Облачного fallback нет. Источники и цитаты сохраняются
в сообщении и отображаются интерфейсом. Если подходящих фрагментов нет,
возвращается «Не знаю». Наличие цитаты само по себе не доказывает качество ответа.

Запуск: `npm start` при работающей Ollama (см. [CHAT.md](CHAT.md)).
Обе модели — `qwen3.5:2b-q4_K_M` и `nomic-embed-text` — должны быть установлены.
Переиндексация существующей книги не требуется.

Проверки:

```powershell
node --test test/*.test.js
node scripts/verify-local-chat.cjs --rag
npm run eval:local-rag
# Передаёт вопросы и фрагменты книги облачному провайдеру:
npm run eval:local-rag -- --cloud
```

Локальный benchmark по умолчанию не читает `.env` и не обращается в облако.
С `--cloud` выбирается доступный DeepSeek, Gemini или OpenRouter.
Один локальный rewrite и поиск на вопрос, одинаковый контекст для обеих
моделей, по два запуска с пустой историей и температурой 0.
Ответы, контекст и время сохраняются в `rag-benchmark.json`.
Время генерации не включает поиск, rewrite и обновление памяти чата;
время поиска и rewrite сохранено отдельно. Первый вызов может включать загрузку модели.
HTTP-проверка использует отдельную временную базу и запрещает внешние fetch.

Итоги реального сравнения: [RAG-RESULTS.md](RAG-RESULTS.md).
