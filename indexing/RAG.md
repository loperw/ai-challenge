# Фильтрация и query rewrite — ветка 23

Пайплайн использует существующие SQLite-индексы и `nomic-embed-text` в Ollama.
Перестраивать индексы и устанавливать отдельную модель реранкинга не требуется.

## Поиск и отбор

1. Изолированный вызов выбранной модели превращает вопрос в поисковый запрос
   с техническими терминами. В историю чата этот служебный вызов не попадает;
   исходный вопрос остаётся вопросом для ответа.
2. Поиск возвращает до `candidateK` фрагментов по исходному запросу и, если
   rewrite отличается, столько же по переписанному. Дубликаты объединяются по `chunk_id`.
3. Для двух выдач применяется Reciprocal Rank Fusion:
   `fusionScore = sum(1 / (60 + rank))`, где первый ранг равен 1.
   Для одного запроса сохраняется порядок cosine similarity.
   Это эвристическое объединение рангов, без отдельной модели cross-encoder.
4. После объединения остаётся общий бюджет до `candidateK` кандидатов.
5. Фильтр оставляет кандидатов с `score >= similarityThreshold`.
   `score` — максимальное cosine similarity по двум запросам; оценки и RRF
   сохраняются отдельно. Фильтр сохраняет порядок, полученный при объединении.
6. До `contextK` оставшихся фрагментов передаются модели. Если прошли два,
   передаются два; если ни одного — модель сообщает об отсутствии контекста.

Similarity — оценка близости векторов, а не вероятность правильного ответа.
Фрагмент по теме может не содержать ответа. Особенно это касается вопросов о
частном проекте или неоднозначных вопросов без истории. Модель должна проверять
достаточность источников и может ответить частично или отказаться даже при непустом контексте.

## Настройки

Во вкладке «Индексы» доступны четыре режима: исходный RAG, только фильтр,
только rewrite, фильтр + rewrite. «Без RAG» по-прежнему отключает поиск в обычном
чате. Режим задач и временные запросы не используют этот пайплайн.

`rag-config.json` содержит начальные настройки. Сервер загружает его при старте;
после изменения файла перезапустите сервер. Настройки интерфейса сохраняются в
localStorage и имеют приоритет над начальными настройками сервера.

* `candidateK`: от 1 до 100, по умолчанию 20.
* `contextK`: от 1 до `candidateK`, по умолчанию 5.
* `similarityThreshold`: от −1 до 1, включительно; равенство порогу проходит фильтр.
* `filter`, `rewrite`: независимые boolean-переключатели.

Порог подбирается отдельно от контрольных вопросов. Разметка использует
физические страницы PDF; она приблизительна. Для другой книги, модели или
стратегии разбиения порог следует проверить заново.

Под ответом сохраняются настройки, исходный запрос, rewrite, кандидаты,
количество удалённых порогом и ограничением K фрагментов, источники ответа.
Расход rewrite сохраняется в `documentSearch.rewrite.tokenStats` отдельно от
расхода основного ответа. Если rewrite не выполнен, интерфейс показывает ошибку
и поиск идёт по исходному вопросу. Ошибка самого поиска возвращается пользователю.

## Сравнение

Кнопка «Сравнить ответы в 4 режимах» использует вопрос из поля поиска.
Четыре ответа создаются с одинаковой моделью, температурой 0 и одинаковыми K,
без истории, профиля и MCP. Переписанный запрос и результаты поиска кешируются
между режимами, чтобы сравнение использовало одни и те же кандидаты.
Поэтому время кешированного поиска нельзя считать временем отдельного режима.

Для воспроизводимого сравнения на наборе вопросов:

```powershell
npm run eval:rag -- --calibrate --answers
```

Скрипт использует `.env` и расходует API-токены для rewrite и ответов.
Ollama должен работать, выбранный индекс должен существовать.
`EVAL_PROVIDER`, `EVAL_MODEL` и `EVAL_STRATEGY` задают модель и стратегию;
по умолчанию это DeepSeek `deepseek-flash` и `structure`.
Для Gemini и OpenRouter укажите соответствующую модель явно.

* 10 калибровочных запросов: 6 с ответом, 4 вне темы.
* Порог перебирается от 0,20 до 0,85 с шагом 0,01. Основной критерий — среднее
  Hit@K для вопросов с ответом и доли пустых контекстов для вопросов без ответа;
  при равенстве предпочтение отдаётся сохранению попаданий и точности по страницам.
* 12 контрольных запросов: 6 с ответом, 6 без ответа, включая близкую тему и неоднозначность.
* С `--answers` генерируются 32 независимых ответа на первых восьми вопросах.
* Без `--answers` сравнивается только поиск; rewrite всё равно вызывает API.
* `--calibrate` записывает выбранный порог в `rag-config.json` только после
  успешного завершения сравнения. Без флага настройки проекта не меняются.

Результаты: `data/evals/rag-<UTC timestamp>/report.json` и `comparison.md`.
Отчёт включает тексты контекстов, ответы, номера использованных источников,
Hit@K, MRR, точность по размеченным страницам и число фрагментов.
Время генерации каждого ответа и расход API также сохраняются.
Хеши кода и индекса позволяют определить, к какой версии относится отчёт.

Набор небольшой: контрольные запросы используют другие формулировки знакомых
тем, а не независимый корпус. Метрики поиска не являются оценкой фактической
правильности ответа. Тексты и обоснованность ссылок нужно проверять отдельно.

Если прогон прерван после калибровки, её можно повторно использовать:

```powershell
npm run eval:rag -- --answers --resume data/evals/rag-<timestamp>/report.json
```

Возобновление разрешено при совпадении кода, набора вопросов, модели, индекса и K.
Контрольный прогон начинается заново; незавершённый отчёт содержит `error`.

## API

`POST /api/document-search`: `{query, strategy, retrievalOptions, settings}`.
`settings` содержит `provider` и `model` для rewrite.
`POST /api/rag-compare` принимает те же поля и возвращает четыре ответа.
`GET /api/rag-config` возвращает начальные параметры.
В `POST /api/chat` параметры передаются как `retrievalOptions` рядом с
`documentStrategy`; для rewrite используется выбранная модель основного чата.

Пример параметров: `{candidateK:20, contextK:5, similarityThreshold:0.76,
filter:true, rewrite:true}`. Отсутствие `retrievalOptions` использует настройки
из `rag-config.json`. CLI `pipeline.py search --top 5` сохраняет исходный поиск
без фильтра/rewrite для совместимости.

## Проверки без платного API

```powershell
node --test
node scripts/document-index.cjs search data/document-index/structure.sqlite "data class"
```

Автотесты RAG используют имитацию модели и поиска: граница порога, пустая выдача,
дубликаты, RRF, бюджет кандидатов, ошибочные настройки, ошибка rewrite,
ошибка поиска, общий rewrite и независимые ответы сравнения.
