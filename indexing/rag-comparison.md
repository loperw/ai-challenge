# Результаты сравнения RAG — ветка 23

Исторический отчёт для лимитов 20 → 5 и четырёх режимов. Текущие настройки
изменены на 7 → 3; доступны исходный RAG и фильтр + rewrite. Приведённые ниже
измерения относятся к прежним настройкам.

Проверка выполнена 5 октября 2026 года по московскому времени на существующем
индексе `structure` книги «Программирование на Kotlin для Android».
Эмбеддинги: `nomic-embed-text`; rewrite и ответы: DeepSeek `deepseek-flash`.
Температура ответов: 0. Кандидатов: 20; итоговый контекст: до 5 фрагментов.
Порог 0,76 выбран на 10 калибровочных вопросах до контрольного прогона.

Контрольная выборка содержит 12 других вопросов: 6 с размеченными страницами
ответа и 6 без ответа. Это другие формулировки знакомых тем, а не независимый
корпус. На первых 8 вопросах получено 32 независимых ответа без истории и MCP.

| Режим | Hit@5 | MRR@5 | Точность по страницам | Пустой контекст для 6 вопросов без ответа | Лишних фрагментов на вопрос без ответа |
| --- | ---: | ---: | ---: | ---: | ---: |
| Без фильтра и rewrite | 2/6 | 0,20 | 0,10 | 0/6 | 5,00 |
| Только фильтр | 2/6 | 0,20 | 0,10 | 1/6 | 2,67 |
| Только rewrite + RRF | 2/6 | 0,25 | 0,10 | 0/6 | 5,00 |
| Фильтр + rewrite + RRF | 2/6 | 0,25 | 0,10 | 0/6 | 3,83 |

Фильтр уменьшил лишний контекст, сохранив число попаданий в размеченные страницы.
Rewrite с объединением рангов поднял фрагмент по lazy с пятого на второе место,
что улучшило MRR. Общее количество вопросов с попаданием не увеличилось.

Совместный режим передавал больше лишнего контекста, чем один фильтр:
максимальная similarity по двум запросам может пропустить дополнительные
нерелевантные фрагменты. Например, после rewrite неоднозначного вопроса
«Для чего они нужны?» появились общие фрагменты о назначении программных
механизмов; без rewrite фильтр оставил пустую выдачу. Исходный вопрос сохраняется
для генерации ответа, но это не гарантирует отсутствие смещения при поиске.

## Проверка ответов и источников

Во всех четырёх режимах модель отказалась отвечать на четыре проверенных
вопроса без ответа: погода, мигрень, Париж, закрытый проект. Для них во всех
16 ответах `usedSources` пуст. Наличие контекста не заставило модель выдавать
ответ о неизвестных фактах.

На четырёх проверенных вопросах с ответом (null, extensions, lazy, data class)
модель не дала полноценного ответа ни в одном режиме. Она сообщала, что
приложенных фрагментов недостаточно. Rewrite иногда добавлял полезные упоминания,
но попадание на размеченную страницу, особенно в чанк на границе страниц,
не гарантирует попадания текста, который объясняет запрошенное поведение.

Следовательно, этот прогон подтверждает сокращение лишнего контекста и
небольшое улучшение позиции одного источника. **Улучшение фактической полноты
ответов на разговорные контрольные вопросы не подтверждено.** Порог similarity
не заменяет оценку того, содержит ли фрагмент ответ. Отдельная модель реранкинга
остаётся возможным дальнейшим развитием; в этой ветке реализованы фильтр и RRF.

## Артефакты и воспроизведение

Полные данные финального прогона:

* `data/evals/rag-2026-10-04T22-03-54-820Z/report.json`: параметры, хеши кода
  и индекса, калибровка, все кандидаты, метрики, 32 ответа, расход API и время ответов.
* `data/evals/rag-2026-10-04T22-03-54-820Z/comparison.md`: ответы четырёх режимов рядом.

Папка `data` исключена из Git. Этот краткий отчёт сохраняется в репозитории.
Предварительные прогоны также находятся в `data/evals`; первый был прерван
ошибкой бюджета контекста сравнения, второй использовал прежний rewrite и
объединение по максимуму similarity. Финальный прогон использует технические
термины в rewrite, RRF и одинаковую инструкцию об обоснованности ответа для всех режимов.

```powershell
npm run eval:rag -- --calibrate --answers
```

Результаты нового прогона могут отличаться: ответы API и rewrite не гарантируют
побитового воспроизведения. Порог нужно проверять заново при смене модели,
книги или стратегии chunking. Подробнее: [настройки и методика](RAG.md).
