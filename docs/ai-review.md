# Автоматическое AI-ревью — ветка 32

PR новой ветки открывается в предыдущую: `codex/ai-challenge-32` → `codex/ai-challenge-31`.
Создание ветки или push без открытого PR не запускают ревью. Слияние для получения ревью не требуется.

`.github/workflows/ai-review.yml` запускается при открытии, обновлении, повторном открытии
и редактировании PR. Целевая ветка не ограничена `main`.

## Пайплайн

1. Получает точные base/head SHA и вычисляет merge-base, список файлов и diff.
2. Читает документацию и код из Git-объектов head: незакоммиченные файлы не участвуют.
3. Повторно использует `buildVectorIndex` / `vectorSearch` из `project-embeddings.js`:
   Ollama `nomic-embed-text`, нормализация, cosine similarity, кэш по содержимому и digest модели.
   Отдельный индекс `data/pr-review-vectors.json` не меняет поведение `/help`.
4. Ищет фрагменты документации и кода по именам изменённых файлов и их diff.
5. Передаёт diff, список файлов и найденные фрагменты DeepSeek `deepseek-flash`.
6. Обновляет один комментарий с разделами «Потенциальные баги», «Архитектурные проблемы»,
   «Рекомендации». Проверяет SHA перед публикацией, чтобы не публиковать устаревшее ревью.

## Настройка GitHub

В Settings → Secrets and variables → Actions добавьте repository secret `DEEPSEEK_API_KEY`.
Код и документация передаются DeepSeek; ключ не включается в промпт и артефакты.
Включите GitHub Actions. Workflow запрашивает `contents: read` и `pull-requests: write`.
Организационная политика должна разрешать публикацию комментариев.
Для PR из forks и Dependabot job пропускается: им не передаются секреты.
Используется GitHub-hosted runner; локальная Ollama пользователя не нужна.
Ollama в контейнере генерирует только эмбеддинги, текст ревью всегда генерирует DeepSeek.

## Локальная проверка

Node.js 24, Git и Ollama с `nomic-embed-text` должны быть доступны.
Ключ берётся из окружения или существующего игнорируемого `.env`.

```powershell
node --test test/pr-review.test.js
node scripts/review-pr.cjs codex/ai-challenge-31 HEAD
node scripts/eval-pr-review.cjs
```

Результаты в `data/pr-review/`: `diff.patch`, `input.json` (контекст, ограничения),
`review.md`, `result.json` (модель, usage, источники). В CI они доступны как артефакт 7 дней.
Ошибка API, отсутствие ключа или эмбеддингов завершают job ошибкой; успешное ревью не имитируется.

`eval-pr-review.cjs` создаёт временный Git-репозиторий с известной регрессией:
обращение к балансу отсутствующего аккаунта вместо возврата нуля по контракту README.
Проверка делает реальные запросы к Ollama и DeepSeek, проверяет наличие обоих типов
RAG-контекста и обнаружение ошибки. Результат сохраняется в `data/pr-review-eval/`.
Редактирование только заголовка/описания PR не запускает повторный анализ; смена base запускает.

## Ограничения

Diff ограничен 60 000 символов; поиск выполняется для первых 12 изменённых файлов,
в промпт входят до 16 найденных фрагментов. Неполный охват явно отмечается в отчёте.
Индексируются отслеживаемые Markdown, JS/TS, Python, YAML, CSS и HTML;
бинарные файлы, symlinks, известные каталоги данных/зависимостей и файлы больше 256 КБ
не индексируются. Файлы секретов исключаются по имени, но это не сканер утечек секретов.
Код PR не запускается анализатором: он читается как текст. Workflow самого PR должен
быть доверенным — это стандартный `pull_request` для веток внутри репозитория.
AI-замечания требуют проверки человеком и сами по себе не блокируют слияние.
