# Ассистент для работы с файлами

Ветка: `codex/ai-challenge-34`, основана на `codex/ai-challenge-33`.

Запуск: `npm start`. В обычном чате выберите DeepSeek, OpenRouter или Gemini,
отключите поиск по индексированным документам. Локальный провайдер пока не использует
MCP-цикл этого приложения. Нужен ключ выбранного провайдера в `.env`.
Лимит токенов диалога установите в 32000 или оставьте пустым: каталог инструментов,
прочитанные файлы и diff также занимают контекст.

Модель сама выбирает файлы и последовательность MCP-вызовов по цели пользователя.
Сервер `workspace` предоставляет `list_files`, `search_files`, `read_file`,
`create_report`, `propose_changes`. Трассировка показывает вызовы и результаты.
Содержимое файлов рассматривается как данные, а не инструкции.

## Сценарий 1: поиск и отчёт

«Найди все использования fetchUser в examples/file-assistant, прочитай определение
и места вызовов, сохрани отчёт examples/file-assistant/reports/api-usage.md
с номерами строк и влиянием изменения параметров».

В демонстрации три исходных файла: `src/api-client.js`, `src/profile.js`,
`src/dashboard.js`. Новый отчёт сохраняется на диск без дополнительного подтверждения, в любой указанной папке проекта (включая «в той же папке»). Повторная запись идентичного
отчёта ничего не меняет; для изменения существующего нужен diff.

## Сценарий 2: документация

«Приведи документацию examples/file-assistant в соответствие с текущим кодом API».

Ассистент проверяет описание аргументов и адрес API в `docs/api.md` и `README.md`.
Если документация уже обновлена предыдущим запуском, новых изменений может не быть.
Ассистент читает исходники и документацию, возвращает diff и останавливается.
Под diff: **«Исправить устаревшие сведения и сохранить изменения?»**, кнопки **Да / Нет**.
Да сохраняет показанное содержимое, Нет отменяет. MCP не предоставляет модели
инструмента одобрения. Изменение исходного файла после подготовки diff вызывает
конфликт до начала записи; нужно попросить новый diff. Повторное решение не
применяет предложение снова. После перезапуска сервера незавершённые предложения
нужно подготовить заново.

## Повторяемая проверка

`npm run test:files` — реальные операции в временных копиях, MCP stdio,
проверка подтверждения, отказа, конфликтов и интерфейса без платного API.
Ответы модели в автоматическом тесте MCP управляемые — это проверка протокола.

`npm run eval:files` — отдельный прогон с реальной моделью и двумя задачами.
По умолчанию DeepSeek / deepseek-flash; настройки: `FILE_ASSISTANT_PROVIDER`,
`FILE_ASSISTANT_MODEL`. Результат: `data/file-assistant/live-results.json`.
Каждый прогон создаёт новую временную копию пяти демонстрационных файлов,
помещает устаревшую документацию только в эту копию,
сохраняет отчёт и оставляет обновление документации на стадии diff без одобрения.
Путь копии записан в результате; оригинальные демонстрационные файлы не меняются.

## Ограничения

Корень по умолчанию — репозиторий приложения; `FILE_WORKSPACE_ROOT` задаёт другой
доверенный каталог при запуске сервера. Запрещены выход за корень, скрытые и
служебные каталоги, ссылки, некоторые чувствительные типы файлов. Разрешены только
текстовые расширения; файлы до 200 КБ, до 1000 файлов в списке и 300 совпадений.
Сокращённые результаты отмечены. Это не полноценный анализатор импортов: модель
анализирует найденный текст и должна явно сообщать ограничения поиска.

Интерфейс diff показывает зелёные добавления, красные удаления и номера строк.
Для Markdown доступен оформленный документ и переключение на точный исходный текст.
Сохранение нескольких файлов
не является транзакцией файловой системы: при ошибке диска возможен частичный
результат, список записанных файлов остаётся в предложении. Не редактируйте
файлы одновременно с сохранением. Доступ к приложению предполагается доверенным,
как и к существующим функциям чата; отдельная многопользовательская авторизация
в этом изменении не добавлена.
