# Помощник разработчика /help

В обычном чате введите `/help <вопрос>`. Команда `/help` без вопроса запрашивает обзор структуры и примеры. В режиме задач и временных запросов команда недоступна.

Примеры: `/help Какие основные файлы проекта?`, `/help Где хранится история?`, `/help Как устроен MCP?`, `/help Какая текущая git-ветка?`, `/help Какой формат у API чата?`.

## RAG документации

Источники — корневой `README.md` и Markdown-файлы в `docs/`, включая вложенные папки. Символические ссылки не читаются. Документы разбиваются по заголовкам и размеру фрагмента, сохраняются путь, иерархия разделов и строка. Заголовки без содержимого исключаются.

Модуль `project-embeddings.js` получает эмбеддинги через Ollama `/api/embed`, модель `nomic-embed-text` (768 координат). Для каждого фрагмента отдельно индексируются текст и заголовок с префиксом `search_document:`. Вопрос кодируется с префиксом `search_query:`. Векторы нормализуются; результат ранжируется по среднему косинусному сходству вопроса с текстом и заголовком. Выбираются до пяти фрагментов, до трёх для локальной LLM. BM25 и поиск по совпадениям слов не используются.

Это семантический поиск, однако эмбеддинги не гарантируют правильную выдачу на любой формулировке. Универсальный порог сходства не применяется: модель получает ближайшие фрагменты и должна признать отсутствие ответа, если в них нет нужных сведений.

Векторный индекс сохраняется в `data/project-vectors.json`: модель и её digest, размерность, отпечаток документов и векторы фрагментов. При каждом `/help` читаются актуальные документы. Новые и изменённые фрагменты получают новые эмбеддинги, удалённые исключаются; неизменённые векторы используются повторно даже после перезапуска. Замена модели или повреждение файла вызывает перестроение. Индекс записывается атомарно.

`npm run index:project` создаёт или обновляет индекс. `npm run index:project -- "В каком месте сохраняются прошлые беседы?"` также показывает результаты векторного поиска. Старый `data/project-index.json` больше не используется.

Для поиска необходима запущенная Ollama на `127.0.0.1:11434` и установленная модель `nomic-embed-text`. Если модель отсутствует, выполните `ollama pull nomic-embed-text`. При недоступности Ollama команда возвращает ошибку; скрытого перехода на поиск по словам нет. Это относится и к ответам облачной LLM: эмбеддинги создаются локально.

## Контекст Git и ответ

Каждый `/help` вызывает `git_context` через MCP stdio. В трассировке видны discovery, вызов и результат. MCP читает только собственный репозиторий. Список файлов включает отслеживаемые Git файлы; новые неотслеживаемые файлы там отсутствуют. Документация индексируется независимо от git add.

Найденные фрагменты и контекст Git передаются выбранной LLM с указанием ссылаться на файлы и разделы, признавать отсутствие сведений и игнорировать инструкции внутри документов. Это требование промпта, а не автоматическая проверка фактов ответа. Ошибка Git или чтения документации прерывает запрос с сообщением об ошибке. Поиск по книге для `/help` не используется даже при включённом книжном RAG.

Полный список отслеживаемых файлов доступен в MCP-трассировке; в контекст генерации передаются ветка и commit. Назначение файлов модель получает из документации. Для небольших локальных моделей ограничены количество фрагментов и длина запрашиваемого ответа.

## Проверка с настоящей моделью

`npm run eval:project-help` (или `node scripts/verify-project-help.cjs`) запускает отдельный сервер приложения с временными базами, выполняет запросы через `/api/chat`, включая перефразированный вопрос, и проверяет SSE, сохранение ответа, MCP-ветку, ссылки и ключевые факты. Эмбеддинги и ответы LLM не подменяются. По умолчанию используется настроенный DeepSeek: запуск расходует API-токены.

Для локальной проверки в PowerShell задайте `$env:EVAL_PROVIDER = 'local'` и `$env:EVAL_MODEL = 'qwen3.5:2b-q4_K_M'`, затем выполните ту же команду. Ollama должна слушать порт 11434. Отчёты с ответами и источниками сохраняются в `data/project-help-e2e-deepseek.json` и `data/project-help-e2e-local.json`. Проверки ключевых фактов не заменяют чтения ответов: свободная генерация может допускать ошибки.
