# Память задачи — ветка 25

В обычном чате и режиме задач память автоматически извлекается из сообщений пользователя: цель, подтверждённые уточнения, ограничения, определения терминов. Отдельные поля не обязательны. Во вкладке «Память агента» кнопка «Редактировать» позволяет заменить значения или очистить их. Сохранение не вызывает модель.

Память находится в `context.taskMemory` существующей SQLite-базы. Она сохраняется независимо от окна последних сообщений и стратегии контекста. Checkpoint и ветки содержат независимые снимки. Новые задачи получают начальную цель из описания. Служебные сообщения управления этапами не извлекаются как пользовательские требования.

Обновление выполняется перед поиском и ответом отдельным JSON-запросом к выбранной модели. Извлекатель сохраняет актуальные записи, заменяет явно исправленные и удаляет отменённые. История служит для разрешения ссылок; предложения ассистента нельзя считать подтверждением пользователя. Вход и размер результата проверяются. При ошибке запроса контекст откатывается. Это не заменяет инварианты и автомат этапов задачи.

Память передаётся основному ответу и query rewrite в режиме «Фильтр + rewrite». При выключенном rewrite поиск, как и раньше, выполняется по исходному вопросу. В режиме задач поиск по книге по-прежнему выключен. Память не является источником фактических утверждений.

`POST /api/task-memory`: `conversationId`, `memory: { goal, clarifications, constraints, terms }`, `expectedVersion`; для ещё не сохранённого чата также `settings`. Возвращает обновлённый `context`. Занятый агент и устаревшая версия дают 409. Цель до 2000 символов; каждый список до 40 строк по 1000 символов.

Каждое обычное сообщение добавляет один вызов модели для памяти. Его расход показан в блоке памяти отдельно от ответа и facts. Режим Sticky Facts сохраняет свой существующий вызов. Внутренние агенты проверки, извлечения и сравнения не запускают рекурсивное извлечение памяти.

## Проверка

`node --test` — проверки хранения, API, отката, изоляции чатов/веток, перезапуска, ручных исправлений, передачи памяти в rewrite и два сценария по 12 ходов с тестовым провайдером. Такие тесты проверяют механизм, но не качество реальной модели.

`node scripts/eval-task-memory.cjs` — два живых сценария по 12 сообщений пользователя и 12 ответов: data class с отвлечением и корутины с исправлением ограничений/термина. Использует DeepSeek, локальный индекс `structure`, текущий порог RAG; сохраняет каждый ход, память, источники и цитаты в `data/evals/task-memory-*/report.json`. После седьмого хода пересоздаёт агента и SQLite-подключение. Окно истории — четыре сообщения. Требует `.env`, доступный API и работающую Ollama. Расходует API-токены и передаёт фрагменты книги модели.

При прерывании: `node scripts/eval-task-memory.cjs --resume data/evals/<каталог>`. Отчёт отдельно считает сохранение цели, допустимые номера источников и буквальное совпадение цитат с нормализацией пробелов. Наличие ссылки не доказывает содержательную достоверность ответа. `unknown` без источников — корректное поведение при недостаточном контексте.
