# RailScout — поиск билетов с AI и уведомлениями в Telegram

RailScout автоматизирует повторную проверку железнодорожных билетов на сайте [БЖД](https://pass.rw.by/). Пользователь задаёт маршрут, дату, время отправления, исключения и типы мест. Приложение показывает подходящие поезда с ценами и может следить за изменениями, отправляя уведомления в Telegram.

Это самостоятельное приложение в каталоге [`ticket-agent/`](ticket-agent/). Интерфейс написан на HTML, CSS и JavaScript, сервер и MCP-инструменты — на JavaScript для Node.js. AI работает через DeepSeek API.

## Какую задачу решает

Например, нужно уехать из Минска в Витебск после 14:00, но до 20:00, только в купе и без отправления в 19:08. Вместо ручного обновления расписания пользователь сохраняет эти условия в мониторинге. Когда найдётся подходящий вариант, бот пришлёт время, доступные места, цены и ссылку «Открыть источник» для перехода к выбору мест.

## Что умеет

- Искать реальные билеты на выбранную дату и показывать результаты в интерфейсе.
- Фильтровать время отправления, исключать конкретное время или интервал.
- Учитывать типы мест: плацкарт, купе, сидячий и СВ.
- Показывать количество мест и цену каждого доступного тарифа.
- Выполнять разовый поиск без Telegram ID.
- Отправлять совпадения в Telegram, если указан ID чата и настроен бот.
- Проверять маршрут каждые 30 секунд, 1, 2, 5, 15 или 30 минут и не повторять одинаковые уведомления мониторинга.

## Где используются AI, MCP и RAG

| Компонент | Его роль в приложении |
| --- | --- |
| **AI / DeepSeek** | При разовом поиске вызывает `search_tickets` и описывает итог. Мониторинг отправляет уведомления напрямую по результатам проверки, не ожидая ответа модели. |
| **MCP** | Связывает веб-сервер с инструментами поиска, мониторинга и отправки Telegram-сообщений. |
| **RAG** | Подбирает подходящие фрагменты локальной справки о типах мест и правилах поиска для контекста AI. Поиск фрагментов основан на совпадении слов. |
| **Обычный код** | Получает расписание, проверяет ограничения, формирует карточки и уведомления, выполняет повторные проверки мониторинга. |

Модели доступен только инструмент поиска. Telegram ID и токен бота в запросы к DeepSeek не включаются. Наличие и цены поступают из источника билетов. При неизменных результатах мониторинга обращений к AI нет. При первом совпадении и последующих изменениях DeepSeek готовит краткий итог для уведомления. Ожидание AI ограничено 5 секундами; при задержке или ошибке бот отправляет данные источника без итога AI.

## Быстрый запуск

Требуется **Node.js 22.5 или новее**. Дополнительные npm-зависимости для RailScout не нужны.

1. Добавьте настройки из [`ticket-agent/.env.example`](ticket-agent/.env.example) в существующий корневой `.env` либо создайте `ticket-agent/.env` по этому образцу. Заполните `DEEPSEEK_API_KEY`. Для уведомлений добавьте `TELEGRAM_BOT_TOKEN`. Настоящие значения хранятся в `.env`, исключённом из Git.
2. Выполните из корня репозитория:

   ```powershell
   npm run start:ticket-agent
   ```

3. Откройте [RailScout на локальном компьютере](http://127.0.0.1:3035).
4. Заполните маршрут и нажмите «Найти подходящие билеты». Для вывода результатов в интерфейсе Telegram ID не требуется.

Если ключи уже находятся в корневом `.env`, повторно создавать файл не нужно. Переменные из `ticket-agent/.env` имеют приоритет над корневым файлом.

## Условия работы

- Мониторинг работает, пока запущены сервер и компьютер. Закрытие страницы или чата разработки его не останавливает. После перезапуска сервера мониторинги нужно создать заново.
- Для открытия выбора мест с телефона можно разместить отдельную статическую страницу из `ticket-agent/link-page/` и указать её адрес в `TICKET_AGENT_LINK_PAGE_URL`. Данные конкретного поезда добавляются в Telegram-ссылку при формировании уведомления. Другой вариант — доступный извне сервер приложения с настройкой `TICKET_AGENT_PUBLIC_URL`.
- Наличие и цены могут измениться после проверки; окончательные данные отображаются на сайте БЖД. Покупку пользователь завершает самостоятельно.
- Текущая интеграция читает HTML расписания. Изменение разметки или ограничение доступа со стороны источника может нарушить поиск.
