# AI Chat — интерфейс для нескольких AI-провайдеров

Небольшое локальное веб-приложение для общения с моделями DeepSeek, OpenRouter и Gemini через API. Оно состоит из чата, изолированного серверного агента и правой панели настроек, где можно выбрать используемую модель и JSON-формат ответа.

## Возможности

- Отправка сообщений в DeepSeek V4.1 Flash, OpenRouter и Gemini API.
- Потоковая выдача: текст ответа появляется по мере генерации.
- Модели разделены в списке на группы DeepSeek, OpenRouter и Gemini 3.5.
- Класс `Agent` хранит контекст диалога, применяет системный промпт и параметры генерации, вызывает API и разбирает потоковый ответ.
- Каждый чат получает отдельный экземпляр агента с изолированным стеком сообщений и сохранением в JSON.
- Восстановление диалогов после перезапуска, счётчик сообщений и очистка всей памяти.
- API-ключ не отображается в браузере и не передаётся клиентскому коду.

## Задачи

Под стрелкой отправки находится компактная кнопка «Задача». Она создаёт задачу прямо из введённого сообщения, закрепляет выбранный профиль и формирует название вида «Задача: …» без дополнительного диалога. Исходный текст сразу становится первым сообщением пользователя в диалоге задачи. Внутренние команды автомата в переписке не показываются. Задача — отдельная сущность: она не смешивается с историей чатов, хранит собственный профиль, сообщения и память и проходит формализованные этапы `planning → execution → validation → done`.

Верхняя шкала показывает этап и текущее действие. На вкладке «Процесс» находятся название, текущий шаг, ожидаемое действие и статусы шагов плана. При планировании агент сначала объясняет, что будет происходить при выполнении и как будет получен результат, а затем формирует только необходимые шаги — обычно один-два, без искусственного дробления. Основная кнопка меняется вместе с состоянием: «Сформировать план», «Утвердить план», «Выполнить шаг …» и «Проверить результат»; нажатия появляются в диалоге как короткие сообщения пользователя с теми же названиями. Внутренние инструкции при этом остаются скрытыми. Паузу можно включить на любом незавершённом этапе; продолжение восстанавливает тот же этап, шаг и план. «Пересмотреть план» открывает отдельный диалог с причиной изменений. После перехода в `done` поле сообщений остаётся доступным.

## Память агента

- Краткосрочная память — сообщения текущего чата. Пользовательские сообщения и ответы агента показаны отдельными пунктами.
- Рабочая память — цели и ограничения текущей задачи. Команда `/working текст` добавляет запись только в активный чат.
- Долговременная память — профиль, решения и знания для всех чатов. Команда `/long текст` делает запись доступной каждому диалогу.

Персонализация вынесена в отдельные профили. В левой панели можно создать пользователя, указать род деятельности, язык, предпочтительный формат ответа и ограничения, выбрать активный профиль или отредактировать и удалить его через кнопку с шестерёнкой. Выбранный профиль добавляется сервером в системный контекст каждого запроса к модели; в истории диалога хранится только идентификатор профиля, а сами профили находятся в отдельной таблице SQLite.

Команды памяти сохраняются без запроса к LLM и помечаются в переписке отдельным оформлением. Краткосрочные сообщения, рабочие записи и долговременная память хранятся в отдельных таблицах SQLite-базы `data/agent-memory.sqlite`; агент добавляет рабочие и долговременные записи в системный контекст перед обычным запросом. Очистка текущего чата удаляет его краткосрочную и рабочую память, но сохраняет долговременную. «Очистить всё» удаляет все три типа.

## Подсчёт токенов

Правая панель показывает оценку текущего запроса (при вводе — черновика), всей истории без приветствий и ошибок, а также вход, ответ и суммарный расход последнего вызова API. История — объём сохранённого текста, а не сумма расходов всех вызовов: прежние сообщения отправляются повторно.

`public/token-counter.js` использует грубую эвристику: 1/4 токена на ASCII-символ и 1/2 на прочие Unicode-символы с округлением вверх. Это не токенизатор модели; оценки помечены ≈ и не включают служебную разметку сообщений. `Agent` читает фактические `usage` / `usageMetadata` из потока, включая финальные события без текста. При отсутствии данных API остаётся оценка. Суммарный расход и выход API могут включать внутренние рассуждения, в зависимости от провайдера.

Поле «Лимит токенов диалога» задаёт общий бюджет истории запросов и ответов, включая системную инструкцию. Перед каждым вызовом агент вычитает оценку всей истории и нового запроса из бюджета, а остаток передаёт как `max_tokens` (DeepSeek/OpenRouter) или `maxOutputTokens` (Gemini). При исчерпании бюджета запрос отклоняется без изменения сохранённой истории. Пустое поле отключает общий лимит. Расчёт приблизительный: используется оценка текста, а не токенизатор конкретной модели.

Форматы статистики: [DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/), [OpenRouter](https://openrouter.ai/docs/cookbook/administration/usage-accounting), [Gemini](https://ai.google.dev/api/generate-content).

## Запуск локально

Для встроенного модуля SQLite требуется Node.js 22.5 или новее.

1. Создайте файл `.env` рядом с `server.js`, скопировав содержимое `.env.example`.
2. Укажите ключи тех сервисов, которыми планируете пользоваться:

   ```env
   DEEPSEEK_API_KEY=ваш_ключ_DeepSeek
   OPENROUTER_API_KEY=ваш_ключ_OpenRouter
   GEMINI_API_KEY=ваш_ключ_Gemini
   AGENT_SYSTEM_PROMPT=необязательный системный промпт агента
   ```

3. Запустите сервер:

   ```bash
   node server.js
   ```

4. Откройте [http://localhost:3000](http://localhost:3000).

Открывать `public/index.html` напрямую как локальный файл не нужно: запросы чата обслуживает Node.js-сервер. Если интерфейс сообщает, что сервер недоступен, снова выполните `node server.js` и обновите страницу по адресу выше.

## Безопасность ключа

Файл `.env` включён в `.gitignore`, поэтому не будет добавлен в Git и опубликован на GitHub. В репозитории остаётся только `.env.example` без настоящего ключа.

При публикации приложения на сервере добавьте нужные переменные окружения (`DEEPSEEK_API_KEY`, `OPENROUTER_API_KEY`, `GEMINI_API_KEY`) в настройках хостинга, а не в исходный код.

`AGENT_SYSTEM_PROMPT` задаёт необязательную общую системную инструкцию. В интерфейсе доступны модель и JSON-режим. История завершённых запросов и ответов сохраняется транзакционно в SQLite-базе `data/agent-memory.sqlite` (исключена из Git) и загружается после перезапуска. При первом запуске существующие `data/conversations.json` и `data/memory.json` автоматически импортируются и остаются резервными копиями. Незавершённый из-за остановки сервера ответ не сохраняется. «Очистить» удаляет текущий диалог, «Очистить всё» удаляет все сохранённые диалоги и локальную копию браузера. Во время генерации очистка памяти отклоняется, чтобы ответ не восстановил удалённый контекст. Счётчик учитывает пользовательские запросы и ответы агента, без приветствий и ошибок.
# Управление контекстом

Переключатель в настройках каждого чата выбирает одну из трёх стратегий. По умолчанию Sliding Window; summary не создаётся и прежнее summary не отправляется модели.

- **Sliding Window**: запрос содержит последние N сообщений, включая текущее сообщение пользователя. После ответа сохраняются только последние N сообщений. Старые сообщения удаляются и не восстанавливаются при увеличении N.
- **Sticky Facts**: перед каждым ответом отдельный вызов выбранной модели обновляет JSON facts (ключи и строковые значения): цели, ограничения, предпочтения, решения, договорённости. Основной запрос содержит facts + последние N сообщений. Старые сообщения удаляются. Некорректные facts или ошибка ответа откатывают весь ход. Расход обновления памяти показан отдельно, вне бюджета основного ответа.
- **Branching**: попросите варианты (например, виды отпуска). После ответа со списком нажмите «Создать ветки из вариантов ответа»: каждый пункт станет отдельной веткой с названием этого вида отпуска. Выберите вариант в селекторе и продолжайте разговор — модель получает выбранную тему вместе с историей ветки. Общая история до списка сохраняется как checkpoint, дальнейшие сообщения каждой ветки независимы. Названия сохраняются при новых ответах. Повторное нажатие для того же ответа не создаёт дубликаты. Поддерживаются нумерованные и маркированные списки, а также Markdown-заголовки. N в этой стратегии не применяется.

Сообщение пользователя и ответ считаются отдельно. Checkpoints, ветки, активная ветка и facts сохраняются в SQLite и восстанавливаются после перезапуска. Checkpoint неизменяем: продолжение ветки его не меняет. Очистка чата удаляет и его ветки. Переход в другую стратегию использует доступные сообщения; ранее отброшенные сообщения не возвращаются. При создании веток checkpoint сохраняется автоматически.
