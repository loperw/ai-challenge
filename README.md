# AI Chat — интерфейс для нескольких AI-провайдеров

Небольшое локальное веб-приложение для общения с моделями DeepSeek, OpenRouter и Gemini через API. Оно состоит из чата, изолированного серверного агента и правой панели настроек, где можно выбрать используемую модель и JSON-формат ответа.

## Возможности

- Отправка сообщений в DeepSeek V4.1 Flash, OpenRouter и Gemini API.
- Потоковая выдача: текст ответа появляется по мере генерации.
- Модели разделены в списке на группы DeepSeek, OpenRouter и Gemini 3.5.
- Класс `Agent` хранит контекст диалога, применяет системный промпт и параметры генерации, вызывает API и разбирает потоковый ответ.
- Каждый чат получает отдельный экземпляр агента с изолированным стеком сообщений и сохранением в JSON.
- Восстановление диалогов после перезапуска, счётчик сообщений и очистка всей памяти.
- API-ключ не отображается в браузере и не передаётся клиентскому коду.

## Запуск локально

1. Создайте файл `.env` рядом с `server.js`, скопировав содержимое `.env.example`.
2. Укажите ключи тех сервисов, которыми планируете пользоваться:

   ```env
   DEEPSEEK_API_KEY=ваш_ключ_DeepSeek
   OPENROUTER_API_KEY=ваш_ключ_OpenRouter
   GEMINI_API_KEY=ваш_ключ_Gemini
   AGENT_SYSTEM_PROMPT=необязательный системный промпт агента
   ```

3. Запустите сервер:

   ```bash
   node server.js
   ```

4. Откройте [http://localhost:3000](http://localhost:3000).

Открывать `public/index.html` напрямую как локальный файл не нужно: запросы чата обслуживает Node.js-сервер. Если интерфейс сообщает, что сервер недоступен, снова выполните `node server.js` и обновите страницу по адресу выше.

## Безопасность ключа

Файл `.env` включён в `.gitignore`, поэтому не будет добавлен в Git и опубликован на GitHub. В репозитории остаётся только `.env.example` без настоящего ключа.

При публикации приложения на сервере добавьте нужные переменные окружения (`DEEPSEEK_API_KEY`, `OPENROUTER_API_KEY`, `GEMINI_API_KEY`) в настройках хостинга, а не в исходный код.

`AGENT_SYSTEM_PROMPT` задаёт необязательную общую системную инструкцию. В интерфейсе доступны модель и JSON-режим. История завершённых запросов и ответов сохраняется атомарно в `data/conversations.json` (исключён из Git) и загружается после перезапуска. Незавершённый из-за остановки сервера ответ не сохраняется. «Очистить» удаляет текущий диалог, «Очистить всё» удаляет все сохранённые диалоги и локальную копию браузера. Во время генерации очистка памяти отклоняется, чтобы ответ не восстановил удалённый контекст. Счётчик учитывает пользовательские запросы и ответы агента, без приветствий и ошибок.
